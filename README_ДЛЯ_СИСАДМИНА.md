# Завод — технический запуск и обслуживание

Документ предназначен для сисадмина или ответственного администратора, который поднимает уже готовую систему «Завод». Это не мастер бизнес-настройки: он не создаёт заводы, пользователей, отделы, роли, линии, чек-листы и другие рабочие сущности.

## Что нужно установить вручную

- Windows с правами на создание папок для данных.
- Docker Desktop с Docker Compose.
- Доступ к папке проекта `C:\Users\79164\Documents\work`.

Мастер установки сам проверит Docker, свободные порты, права записи и здоровье сервисов.

Если Docker Desktop установлен, но команда `docker --version` не работает в PowerShell, можно временно указать путь к CLI перед запуском мастера:

```powershell
$env:ZAVOD_DOCKER_EXE="C:\Program Files\Docker\Docker\resources\bin\docker.exe"
```

Мастер также сам проверяет типовые пути Docker Desktop.
В окне установки есть необязательное поле «Путь к docker.exe» — его можно заполнить, если Docker установлен нестандартно.

## Быстрый старт

1. Откройте файл `Установка Завод.cmd`.
2. В локальном окне мастера проверьте окружение.
3. Укажите адрес сервера, порты backend/frontend и папки хранения.
4. Нажмите «Проверить».
5. Если все пункты зелёные, нажмите «Установить и запустить».

Если runtime-конфиг уже существует, мастер покажет предупреждение и попросит отметить чекбокс. Старый конфиг будет сохранён backup-копией с датой и временем, затем будут записаны новые технические настройки.

После успешной установки мастер покажет:

- backend health URL;
- frontend URL;
- папку runtime-конфига.

## Команды в корне проекта

- `Установка Завод.cmd` — открывает локальный мастер установки.
- `Запуск Завод.cmd` — запускает Docker Compose сервисы.
- `Остановка Завод.cmd` — останавливает сервисы без удаления данных.
- `Проверка Завод.cmd` — проверяет Docker, конфиг, папки, backend `/health`, frontend, PostgreSQL и миграции.
- `Бэкап Завод.cmd` — создаёт полный backup БД, uploads и runtime-конфига.
- `Восстановление Завод.cmd` — открывает аварийный мастер восстановления из backup.
- `Создать ярлыки Завод.cmd` — создаёт ярлыки команд на рабочем столе.

## Где хранится технический конфиг

По умолчанию runtime-конфиг создаётся в:

`setup\runtime`

Внутри:

- `zavod.config.json` — адреса, порты и папки хранения;
- `production.env` — технические секреты и переменные Docker Compose.

Эта папка добавлена в `.gitignore`. Её нельзя коммитить, отправлять в чат или публиковать.

Если файл конфига уже существует, мастер перед записью создаёт backup-копию с timestamp.

Проверка установки также убеждается, что в проекте доступны `backend/prisma/schema.prisma` и папка миграций `backend/prisma/migrations`.

## Данные и папки

Мастер предлагает отдельные папки для:

- данных PostgreSQL;
- uploads / вложений;
- backups;
- файловых копий сообщений об ошибках;
- logs.

Установка не удаляет существующие данные. Restore — отдельная аварийная операция и запускается только через отдельный мастер с явным подтверждением.

Папка файловых копий сообщений об ошибках нужна для handover: каждое сообщение из раздела «Сообщить об ошибке» остаётся в БД и в ADMIN-экране, а дополнительно сохраняется отдельным пакетом на диске. В пакете есть `report.html`, `report.txt`, `manifest.json` и папка `attachments/` с копиями доступных вложений. Полный серверный путь не показывается обычным пользователям в приложении.

## Backup

`Бэкап Завод.cmd` создаёт dated backup в настроенной папке backups.

В backup входят:

- PostgreSQL dump;
- uploads;
- runtime config;
- manifest;
- checksums.

Файловые копии сообщений об ошибках являются производным эксплуатационным слоем: исходные данные остаются в БД и uploads, а путь к папке фиксируется в runtime config. Если нужно отдельно архивировать эту папку для сисадмина, делайте это как защищённый operational artifact, не отправляя его в чат и не коммитя в репозиторий.

Backup является секретным эксплуатационным артефактом. В нём есть дамп БД и runtime-конфиг. Его нельзя отправлять без защиты, коммитить или хранить в общедоступном облаке.

## Restore

`Восстановление Завод.cmd` открывает аварийный мастер восстановления.

Перед реальным восстановлением мастер:

- проверяет выбранный backup;
- требует ручное подтверждение словом `ВОССТАНОВИТЬ`;
- создаёт предвосстановительный backup текущего состояния;
- сохраняет прежнюю uploads-папку с timestamp, а не удаляет её физически.

Restore заменяет текущую БД и uploads. Не используйте его для обычной проверки.

## Проверка после запуска

После запуска проверьте:

- `Проверка Завод.cmd`;
- backend `/health`;
- frontend URL из мастера;
- вход в систему штатными ролями;
- открытие вложений;
- создание тестовой записи только если это согласовано с владельцем проекта.

## Что мастер не делает

- Не создаёт бизнес-объекты.
- Не делает DB reset/drop/truncate.
- Не удаляет uploads.
- Не очищает историю.
- Не меняет реальные рабочие данные.
- Не заменяет пилотную проверку на телефоне.

## Если установка не проходит

Чаще всего причины такие:

- Docker Desktop не установлен или не запущен.
- Docker установлен, но `docker.exe` недоступен в `PATH` и не найден в типовых путях.
- Порты backend/frontend заняты.
- Нет прав записи в выбранные папки.
- Не найдены Prisma schema или migrations.
- Диск заполнен.
- Антивирус блокирует Docker volume или папку backup.

Исправьте причину и снова запустите `Установка Завод.cmd` или `Проверка Завод.cmd`.
