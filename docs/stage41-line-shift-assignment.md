# Stage 41 — Текущее задание линии

## Назначение

“Текущее задание” — это необязательный оперативный план линии на смену. Он нужен мастеру и следующей смене, чтобы видеть, что линия сейчас делает и сколько гофр запланировано.

Это не 1С, не ERP, не складской учёт, не учёт партий и не расчёт себестоимости. Блок не заменяет итоговый процент выполнения плана линии.

## Модель

План хранится по связке:

- завод;
- производственная линия;
- дата смены;
- тип смены: дневная или ночная;
- опционально активная `ShiftSession`, если она уже существует.

Такой вариант поддерживает текущую смену и будущую смену до создания `ShiftSession`. Когда смена уже есть, `shiftSessionId` остаётся связью с ней, но не является единственным ключом.

Строки задания:

- артикул;
- наименование;
- гофр по плану;
- порядок.

Пустые строки не сохраняются. Максимум — 10 заполненных строк на линию и смену.

## Права

Чтение доступно пользователям, которые видят линию в выбранном заводе.

Редактирование доступно:

- `MASTER`;
- `MANAGEMENT`;
- `ADMIN`;
- пользователям с правами `lines.manage`, `assignments.manage`, `shift.manage` или `lines.assignment.manage`.

`WORKER`, `CONTRACTOR` и `CONTRACTOR_LEAD` не редактируют задание. Прошлые смены доступны только для просмотра.

Backend guard остаётся источником истины: frontend скрывает кнопки только для удобства.

## API

Добавлены endpoints внутри существующего контура линий:

- `GET /lines/:lineId/shift-assignment`;
- `PUT /lines/:lineId/shift-assignment`;
- `PATCH /lines/:lineId/shift-assignment/rows`;
- `DELETE /lines/:lineId/shift-assignment/rows/:rowId`.

Параметры выбора смены:

- `shiftSessionId`;
- или `shiftDate` + `shiftType`;
- если параметры не переданы, используется активная смена пользователя или текущая дата и текущий тип смены.

## UI

В сменном dashboard линии добавлена кнопка “Текущее задание”.

Если строк нет, пользователь видит:

> Задание не заполнено

Для ролей с правом редактирования доступна кнопка “Добавить строку”. Удаление строки идёт через безопасное подтверждение, без `prompt/alert/confirm`.

На мобильном экране строки показываются карточками, без широкой таблицы.

## Пересменка

Задание не дублируется в пересменке. Оно помогает следующей смене понять текущий оперативный план линии, а пересменка остаётся журналом важных событий и комментариев.

## Аудит

Пишутся действия:

- `LINE_SHIFT_ASSIGNMENT_UPDATED`;
- `LINE_SHIFT_ASSIGNMENT_ROW_ADDED`;
- `LINE_SHIFT_ASSIGNMENT_ROW_UPDATED`;
- `LINE_SHIFT_ASSIGNMENT_ROW_DELETED`;
- `ACCESS_DENIED`.

Аудит хранит старые и новые значения, но не содержит секретов.

## Regression

Проверяется:

- создание и обновление строк;
- ограничение 10 строк;
- пустые строки не сохраняются;
- текущая и будущая смена редактируются;
- прошлая смена read-only;
- `WORKER` и `CONTRACTOR_LEAD` не редактируют;
- `MASTER`, `MANAGEMENT`, `ADMIN` редактируют;
- cross-factory и blocked denied;
- audit actions.
