# Stage 42 — Operational Closure Pack

## Discovery result

Stage 42 не добавляет новый модуль. Он связывает уже существующие контуры:

- `LineEvent` хранит события линии, причины простоя и Stage40B-поля корректировки времени.
- `Task` уже имеет `lineId` и `lineStatusEventId`, поэтому заявка может быть явно связана с простоем.
- `Archive` уже считает effective downtime через `correctedStartAt/correctedEndAt` и умеет открывать исходный раздел через `sourceRoute`.
- `Notification` уже хранит `entityType/entityId`; Stage42 добавляет удобный `sourceRoute` в выдачу.
- `DefrostEvent` остаётся календарём оттайки; Stage42 добавляет только лёгкую сводку за 30/60 дней.

## Line downtime UX

В dashboard линии действия теперь формулируются как рабочий поток:

- `Зафиксировать простой`;
- причина простоя из русского списка;
- комментарий к событию;
- `Вернуть в работу`;
- `Уточнить время простоя`.

Причины простоя нормализованы, но в UI показываются по-русски:

- техническая неисправность;
- нарушение технологии;
- качество / ОКК;
- оттайка;
- мойка;
- нет людей;
- нет сырья / склад;
- ожидание решения;
- другое.

Корректировка времени использует существующий endpoint Stage40B `/archive/downtime/:eventId/correction`. Комментарий обязателен, старые и новые значения пишутся в audit.

## Task from downtime

В dashboard линии при активном простое появляется действие `Создать заявку из простоя`.

Созданная заявка получает:

- `lineId`;
- `lineStatusEventId`;
- выбранный отдел-получатель;
- тип `URGENT`;
- описание.

Такую заявку видит адресованный отдел, а Stage40B-аналитика учитывает её как связанную с простоем. Заявки без явной связи не считаются причиной простоя.

## Notification links

Список уведомлений возвращает `sourceRoute` для известных объектов:

- заявка → `Заявки`;
- заказ / остаток → `Заказы / Остатки`;
- оттайка → `Оттайка`;
- объявление → `Объявления`;
- пересменка → `Пересменка / Журнал`;
- мойка → `Мойка`;
- чек-лист → `Чек-листы`.

Если точного detail-route нет, кнопка `Открыть` ведёт в исходный раздел. Backend guards исходного раздела остаются источником истины.

## Archive source links

Архив продолжает быть единым просмотрщиком, а не отдельным хранилищем. `Открыть источник` ведёт в исходный раздел и не расширяет права доступа.

## Defrost light summary

В календаре оттайки добавлена лёгкая сводка:

- период 30 / 60 дней;
- количество оттаек;
- обычное время оттайки;
- обычное рабочее время между оттайками;
- рабочих дней линии, если такие данные можно честно получить.

Если данных недостаточно, экран показывает `Недостаточно данных для расчёта`. Это не BI и не глубокая аналитика оттайки.

## Stock archive polish

Stage40A-метрики остатков сохранены:

- `Израсходовано за период`;
- `Пополнено за период`.

Цены, партии, поставщики, себестоимость и 1С не входят в Stage42.

## RBAC / scope

Проверяемые правила:

- WORKER/CONTRACTOR не фиксируют простой и не создают управленческие заявки из простоя.
- MASTER/MANAGEMENT/ADMIN работают с линией по правам.
- Адресованный отдел видит связанную заявку.
- Чужой пользователь не может взять чужую заявку.
- Ссылки уведомлений и архива не обходят backend guards.
- blocked/cross-factory доступ запрещён.
