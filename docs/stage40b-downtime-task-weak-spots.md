# Stage 40B — Простои, заявки и аналитика слабых мест

## Discovery result

Простой уже фиксировался через `LineEvent`: смена статуса линии `PAUSE` или `STOP` означает начало простоя, следующий `WORK` по той же линии означает запуск линии в работу. Заявки уже имеют `lineId`, `startedAt`, `doneAt`, `deadlineAt`, адресованные отделы, исполнителей и `TaskHistory`.

Для честной аналитики не хватало явной связи заявки с конкретным событием простоя и корректировки фактического времени. Stage40B добавляет только additive-поля в существующие сущности, без отдельной таблицы архива и без нового модуля заявок.

## Модель простоя

Простой считается интервалом:

- начало: `LineEvent.status = PAUSE | STOP`;
- окончание: следующий `LineEvent.status = WORK` по той же линии;
- причина: `downtimeReason`, либо нормализация по комментарию;
- effective start: `correctedStartAt ?? createdAt`;
- effective end: `correctedEndAt ?? confirmedEndAt ?? next WORK time`;
- длительность: `effectiveEndAt - effectiveStartAt`.

Поддерживаемые причины:

- техническая неисправность;
- нарушение технологии;
- качество / ОКК;
- оттайка;
- мойка;
- нет людей;
- нет сырья / склад;
- ожидание решения;
- другое.

## Корректировка времени

Закрытый простой можно уточнить через действие “Уточнить время простоя”. Обязателен комментарий. Старое и новое значения пишутся в audit action `LINE_DOWNTIME_CORRECTED`.

Корректировка не удаляет старое событие и не переписывает историю молча: аналитика использует effective-время, а audit хранит old/new values.

## Связь простоев и заявок

Заявка считается связанной с простоем только при явной связи:

- `lineStatusEventId`;
- либо `lineId` и время создания попадает в интервал простоя этой линии.

Заявки без линии участвуют в статистике отделов и исполнителей, но не попадают в метрики простоев линии.

## API

Добавлены read endpoints в существующий `ArchiveModule`:

- `GET /archive/downtime/summary`;
- `GET /archive/downtime/by-lines`;
- `GET /archive/downtime/by-departments`;
- `GET /archive/downtime/by-assignees`;
- `GET /archive/downtime/items`;
- `GET /archive/downtime/options`;
- `POST /archive/downtime/:eventId/correction`.

Архив и аналитика не расширяют доступ: используются права исходных заявок, линий и заводской scope.

## Метрики

По простоям:

- количество простоев;
- общая длительность;
- средняя длительность;
- медиана;
- p90;
- линии с наибольшей длительностью;
- причины простоев.

По заявкам:

- всего;
- закрыто;
- открыто;
- открытые на конец периода;
- просроченные LONG;
- среднее/медиана/p90 реакции;
- среднее/медиана/p90 выполнения;
- среднее/медиана/p90 полного решения.

По исполнителям используется нейтральная формулировка: участие в устранении, взял заявок, закрыл, связано с простоями.

## Фильтры и UI в архиве

В `Архив → Заявки и простои` добавлены вкладки:

- Сводка;
- По линиям;
- По отделам;
- По исполнителям;
- Просроченные;
- Детальный список.

Фильтры работают по периоду, дневной/ночной смене, линии, отделу, исполнителю, типу заявки, статусу, причине простоя и признаку “только связанные с простоем”. Фильтр день/ночь вычисляется по времени начала события или заявки: дневная смена — 08:00–19:59, ночная — остальные часы.

Карточки KPI показывают “Общая длительность простоев”, “Среднее время реакции”, “p90 решения”, “Проблемные линии”, “Нагрузка по отделам”, “Участие исполнителей” и “Открытые на конец периода”. На 360px вкладки и карточки остаются в карточной сетке без горизонтального переполнения.

## RBAC / scope

- `ADMIN` видит выбранный завод.
- `MANAGEMENT` ограничен своим scope.
- `MASTER` и технические роли видят доступные линии/заявки.
- `WORKER`, `CONTRACTOR`, `CONTRACTOR_LEAD` не получают управленческую аналитику.
- blocked/cross-factory доступ запрещён.

## Regression checklist

Stage40B закрывается проверками:

- `stage40b:downtime-task-analytics-regression`;
- `stage40b:browser-e2e`;
- affected gates: `stage10:tasks-regression`, `stage35:browser-e2e`, `stage39:*`, `stage40a:*`;
- Prisma validate/generate/migrate status;
- backend/frontend build;
- `stage30:release-readiness-regression`;
- `node --check backend/prisma/seed.js`;

- mojibake и visible-English scan.

## Не входит в Stage40B

- BI по всем разделам;
- аналитика ОКК и возвратов;
- ERP/1С/партии/цены/себестоимость;
- обвинительная статистика по людям;
- автоматические рекомендации штатного расписания.
