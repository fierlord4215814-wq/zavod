# Stage57 — Factory Setup Wizard

## Discovery result

Существующий контур админки уже содержит нужные модели для конфигурации завода: `Factory`, `Department`, `Line`, `LinePosition`, `LineStaffingTemplate`, `LineStaffingTemplateItem`, `WorkArea`, `WorkAreaPosition`, `JobTitle` и настройки модулей. Runtime-данные живут отдельно: смены, назначения, события линий, заявки, мойка, ОКК, складские журналы, чаты, вложения, объявления, аудит и уведомления.

Новый отдельный модуль не нужен. Stage57 расширяет существующие `AdminModule`, `AdminService`, `AdminController` и `AdminConfigScreen`.

## Migration

Миграция не нужна. Все данные, которые копирует мастер настройки, уже есть в схеме. Копирование выполняется через новые backend endpoints и транзакцию.

## API

- `GET /admin/factories/setup/options` — варианты завода-источника и категории копирования.
- `POST /admin/factories/setup/preview` — dry-run предпросмотр без записи в БД.
- `POST /admin/factories/setup/create` — создание завода и optional копирование конфигурации.
- `GET /admin/factories/:id/config-health` — проверка готовности конфигурации выбранного завода.

Backend guard остаётся источником истины: endpoints доступны только ADMIN по существующему admin guard. Заблокированные пользователи и пользователи без прав получают отказ.

## Что можно создать

Мастер поддерживает два режима:

- `Пустой завод` — создаёт завод и базовые настройки модулей, если выбрана категория настроек.
- `Скопировать с завода` — копирует выбранные категории конфигурации из завода-источника.

Категории копирования:

- локальные отделы;
- общие службы как references/foundation без выдачи доступа людям;
- линии;
- позиции линий;
- шаблоны состава и строки шаблонов;
- рабочие зоны;
- позиции рабочих зон;
- должности foundation;
- настройки модулей.

После создания текущий администратор получает `ADMIN` доступ к новому заводу. Остальные пользователи и доступы не копируются автоматически.

## Что не копируется

Мастер намеренно не копирует runtime:

- `ShiftSession`;
- `Assignment`;
- `PlannedLineAssignment`;
- `ShiftWillBe`;
- `LineShiftWorkPlan`;
- `LineEvent` и простои;
- `Task`, `TaskHistory`, комментарии и чтения;
- `WashSession`;
- ОКК, возвраты, некондиция, заказы и движения остатков;
- чаты, сообщения и read state;
- вложения;
- объявления и ознакомления;
- аудит;
- уведомления;
- пользовательские сессии;
- доступы пользователей к заводу, кроме текущего администратора.

Это принципиально: Stage57 создаёт стартовую конфигурацию, а не клон истории.

## Config health

После выбора или создания завода админка показывает проверку конфигурации:

- нет активных линий;
- линия без позиций;
- линия без активного шаблона состава;
- шаблон без строк;
- рабочая зона без позиций;
- отдел без пользователей;
- должность без отдела или preset;
- нет admin/management доступа;
- нет настроек смен или заявок;
- позиции без `skillCode`.

Проверка показывает блокеры, предупреждения и то, что уже настроено. Она не исправляет данные автоматически и не скрывает проблемы.

## UI

В `Админка → Заводы` добавлен мастер:

1. Основные данные.
2. Способ настройки.
3. Предпросмотр.
4. Проверка здоровья.

Создание идёт через safe modal `AdminConfirmDialog` с обязательным вводом `ЗАВОД`. Browser `prompt/alert/confirm` не используются.

На mobile 360px мастер остаётся карточным, без широкой таблицы и горизонтального overflow.

## Audit / security

Пишутся audit actions:

- `FACTORY_CREATED`;
- `FACTORY_CONFIG_CLONED`;
- `FACTORY_SETUP_COMPLETED`;
- `FACTORY_CONFIG_HEALTH_VIEWED`.

Ответы API не отдают `storagePath`, `passwordHash`, token/secret поля и runtime-историю.

## Compatibility

Старый endpoint создания завода сохранён для совместимости с предыдущими stage/gates. Stage57 UI использует новый setup flow.
