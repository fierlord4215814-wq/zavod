# Stage60 — Admin Safety / Recovery Center

## Discovery result

Существующая админка уже управляет заводами, отделами, должностями, линиями, позициями, шаблонами состава, рабочими зонами и доступами пользователей через `AdminConfigScreen`, `AdminController` и `AdminService`. Отдельный модуль восстановления не нужен: безопаснее расширить текущий admin-контур и сохранить backend guards как источник истины.

У большинства защищённых сущностей уже были признаки мягкого отключения: `isActive` и/или `deletedAt`. Не хватало только человекочитаемой причины, автора отключения, окна восстановления и единого экрана, где администратор видит отключённые объекты.

## Migration

Нужна safe additive migration. Она добавляет nullable-поля:

- `deactivatedAt`
- `deactivatedById`
- `deactivationReason`
- `recoveryUntil`
- `restoredAt`
- `restoredById`

Поля добавлены к защищённым объектам: заводы, отделы, должности, доступы к заводу, линии, позиции линий, шаблоны состава, рабочие зоны и позиции рабочих зон. Миграция не удаляет данные и не меняет существующую историю.

## Protected objects

Физическое удаление из UI не используется для важных настроек. Отключение переводит объект в безопасное состояние и записывает причину:

- завод;
- отдел / общая служба;
- должность;
- доступ пользователя к заводу;
- производственная линия;
- позиция линии;
- шаблон состава;
- рабочая зона;
- позиция рабочей зоны.

## Recovery center

В админке добавлен раздел `Восстановление`.

Администратор видит:

- тип объекта;
- название;
- завод / родительский объект;
- кто отключил;
- когда отключил;
- причину;
- срок восстановления;
- действие `Восстановить`.

Окно восстановления Stage60: минимум 30 дней. Объекты не удаляются физически: история смен, заявок, аудита и вложений остаётся.

## Dangerous actions

Отключение защищённых объектов требует причину в безопасной модалке приложения. Browser `prompt/alert/confirm` не используется.

Восстановление возвращает объект в рабочие списки и пишет audit. Если объект восстановлен, поля отключения очищаются, а `restoredAt/restoredById` заполняются.

## Last admin guard

Нельзя убрать последнего активного администратора завода. При попытке backend блокирует действие и пишет audit action `LAST_ADMIN_GUARD_BLOCKED`.

## RBAC / security

Backend guards остаются источником истины:

- только `ADMIN` управляет Recovery Center;
- обычные пользователи не открывают восстановление;
- blocked user получает отказ;
- cross-factory доступ не расширяется;
- responses не отдают `storagePath`, `passwordHash`, tokens, secrets.

## Audit

Stage60 пишет audit для:

- отключения защищённого объекта;
- восстановления из Recovery Center;
- блокировки last-admin действия;
- `ACCESS_DENIED` остаётся диагностическим действием текущего security контура.

## UI policy

В pilot UI опасные действия называются `Отключить`, `Деактивировать`, `Архивировать` или `Восстановить`, а не `Удалить`.

Администратор видит причину и последствия действия до подтверждения. На mobile 360px recovery cards отображаются карточками, без широкой таблицы.

## What remains future

- отдельный retention dashboard по срокам восстановления;
- расширенная фильтрация recovery по типу и периоду;
- экспорт отчёта восстановления;
- более глубокие сценарии восстановления зависимостей, если объект связан с большим количеством отключённых родителей.
