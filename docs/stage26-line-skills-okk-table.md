# Stage 26 — Навыки на линиях и таблица брака ОКК

## Discovery

Line/staffing/skills: PARTIAL. В проекте уже были `LinePosition`, `LineStaffingTemplate`, `LineStaffingTemplateItem`, `UserSkill`, доска назначений и экран людей/навыков. Stage 26 расширяет эти сущности additive: min/max/planned слоты, `skillCode`, `skillFamilyKey`, переносимые похожие навыки и optional extra slots.

OKK: PARTIAL. В проекте уже был модуль ОКК с `OkkRecord`, статусами, вложениями, архивированием и guard-логикой. Stage 26 расширяет существующий `OkkRecord` под Excel-таблицу брака, не создавая второй OKK-модуль.

## Line staffing

Позиция линии теперь хранит:

- `displayName` — название без кода навыка;
- `skillCode` — код из скобок, например `К`, `П`, `Ко`;
- `skillFamilyKey` — связка нормализованного названия позиции и кода;
- `isExtraSlot` и `doesNotAffectShortage` для строки `Дополнительно`.

Шаблон состава хранит:

- `minRequired`;
- `maxRequired`;
- `defaultPlanned`;
- `plannedCount`;
- `isFlexible`.

Фиксированное значение `1` превращается в `min=1/max=1/default=1`. Диапазон `2-4` превращается в `min=2/max=4/default=2`. Слот `Дополнительно` не влияет на shortage.

## Similar skills

Прямой навык `lineId + positionId` считается лучшим совпадением. Если у сотрудника есть активный навык с таким же `skillFamilyKey` на другой линии, кандидат получает пометку `Схожий навык`. Одинаковая буква без совпадения позиции не считается одинаковым навыком.

## Assignment board

Доска назначений использует `plannedCount` для количества слотов. Flexible-слоты показывают план в пределах min/max. Кандидаты остаются только WORKER/CONTRACTOR; прямое назначение MASTER/OKK/STORE/ADMIN backend по-прежнему запрещает.

## OKK defect table

`OkkRecord` расширен под поля Excel:

1. дата;
2. дата изготовления;
3. смена;
4. артикул;
5. наименование продукции;
6. причина несоответствия;
7. количество забракованной продукции;
8. принятое решение;
9. мастер;
10. температура после доп. заморозки;
11. отметка о выполнении;
12. дата разбраковки;
13. кто выполнил / разбраковал;
14. кто забраковал;
15. корректирующие действия.

Поля 1–10 заполняются при создании записи. Поля 11–15 заполняются через действие `Отметить выполнение`. Действие `Полностью завершён` доступно после финальных полей и переводит запись в архив без физического удаления.

## RBAC

- `okk.read` видит таблицу и архив по scope.
- `okk.manage` создаёт, редактирует и завершает записи.
- WORKER/CONTRACTOR остаются forbidden.
- MANAGEMENT/ADMIN имеют обзор/архив по существующим правам, бизнес-редактирование остаётся за `okk.manage`.
