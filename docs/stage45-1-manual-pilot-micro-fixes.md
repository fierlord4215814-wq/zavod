# Stage45.1 Manual Pilot Micro-Fixes

## Discovery result

После ручного pilot-просмотра подтвердились не отдельные сбои, а слой UX-шероховатостей:

- рабочие списки местами показывали Stage/regression/demo записи;
- в кандидатах назначения попадались технические `worker-1` и Stage-пользователи;
- порядок вкладок смены был неестественным для мастера;
- список запуска линий мог показывать тестовые/дублирующие линии;
- действия в длинных модалках приходилось искать прокруткой;
- права в админке показывались техническими кодами;
- профиль пользователя в админке был недостаточно надёжно покрыт;
- в заявках мог протекать выбранный файл из предыдущего действия;
- ОКК-журнал был слишком плотным текстовым блоком.

Часть проблем была вызвана накопленными Stage*/regression fixtures. Историю не удаляли физически: такие записи остаются доступными в архиве/diagnostics по правам, но скрываются из pilot runtime списков.

## Что исправлено

- Добавлен общий helper pilot-видимости для backend и UI.
- Runtime списки линий, людей, кандидатов, задач и активных ОКК-записей скрывают Stage/test/demo/regression noise.
- Заблокированные и fixture-пользователи не попадают в кандидаты назначений.
- Технические seed ids отображаются как человекочитаемые имена: `worker-1` -> `Работник 1`, `contractor-1` -> `Наёмный работник 1`.
- Вкладки смены идут в порядке: `Прошлые`, `Текущая`, `Будущие`.
- Запуск линии использует только pilot-visible production lines выбранного завода и закрывает модалку после успешного подтверждения.
- Повременщики получили более явные кнопки `Назначить` / `Выбрать сотрудника`, без мелких `+/-` как основного UX.
- Длинные модалки получили sticky action footer.
- Админка показывает русские названия прав, а технический code остаётся только в `title`/advanced context.
- Список пользователей админки скрывает Stage fixtures и открывает профиль с человекочитаемым именем.
- В заявках файл из предыдущего действия больше не протекает в `Готово`, `Передать`, `Комментарий`.
- ОКК-записи отображаются как журнал: отдельные поля с подписями и отдельным блоком действий.

## Fixture strategy

Правило Stage45.1:

- не делать physical delete;
- не скрывать реальные производственные записи;
- Stage/test/demo/regression маркеры скрывать только из рабочих runtime списков, где они мешают pilot UI;
- архив и audit сохраняют историю по исходным правам;
- blocked users не показываются как кандидаты.

## Custom roles decision

Полноценное создание кастомных должностей/ролей не добавлялось в Stage45.1. Discovery показал, что текущий RBAC завязан на enum-ролях и матрице `RolePermission`; безопасное расширение до custom roles требует отдельного архитектурного этапа. В pilot UI вместо этого убраны первичные английские permission codes и добавлены русские labels.

## Regression checklist

- `stage45_1:manual-pilot-micro-fixes-regression` проверяет backend-фильтрацию, line activation, task take/redirect, admin profile, OKK active list, cross-factory/blocked guards.
- `stage45_1:browser-e2e` проверяет human UX на смене, линиях, повременщиках, задачах, ОКК, админке и mobile 360px.

## Что проверить руками

- Открыть `Смена` мастером и проверить, что в списках нет Stage/test линий и пользователей.
- Запустить производственную линию и убедиться, что модалка закрылась, а линия появилась в активных.
- Открыть `Повременщики` и проверить назначение через понятные кнопки.
- Открыть `Заявки`, взять/передать заявку и убедиться, что история содержит комментарий, а не случайный файл.
- Открыть `Администрирование -> Пользователи -> Профиль`.
- Открыть `Роли и права` и проверить, что основные подписи прав русские.
- Открыть `ОКК` и проверить читаемость журнала на desktop/mobile.

## Future

- Отдельный этап для custom roles/job titles поверх существующего enum-RBAC.
- Более глубокий pilot-mode switch для диагностических экранов, если понадобится показывать/скрывать fixtures управляемо.
- Тонкая настройка человекочитаемых имён для реальных ФИО после подключения production справочника.
