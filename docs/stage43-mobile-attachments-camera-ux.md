# Stage 43 — мобильные вложения, камера и формы

## Что закрыто

Stage 43 доводит уже существующий attachment foundation: новый файловый модуль, новое хранилище и offline binary sync не добавлялись. Вложения по-прежнему хранятся через существующий `Attachment` и guarded download endpoint, а доступ проверяется по исходному объекту.

## Единый UX вложений

Общий `AttachmentPicker` используется как единая точка выбора файлов:

- кнопка `Сделать фото` открывает камеру на телефоне, если браузер поддерживает `capture`;
- кнопка `Добавить фото или файл` открывает выбор поддержанных файлов;
- выбранный файл показывается до отправки;
- отображаются имя, тип и размер;
- файл можно убрать до загрузки;
- ошибки типа и размера показываются на русском;
- видео доступно только там, где оно уже разрешено бизнес-логикой, например в чатах.

`AttachmentPreviewList` показывает русские подписи для фото, видео и файлов, открывает preview/download через guarded endpoint и умеет показывать пустое состояние `Вложений нет.` там, где экран явно просит пустое состояние.

## Где поддержаны вложения

Проверены существующие контуры:

- заявки и комментарии к заявкам;
- ОКК;
- возвраты на производство;
- чек-листы;
- чаты, включая фото/видео/файлы;
- некондиция;
- мойка;
- заказы/остатки;
- пересменка;
- архив `Файлы и вложения`.

Объявления показывают вложения, если они уже прикреплены и доступны через backend guard. Отдельный новый flow загрузки в объявления Stage 43 не добавляет.

## Camera Behavior

На мобильном браузере поле `capture="environment"` помогает открыть камеру для фото. Если камера недоступна или браузер игнорирует `capture`, остаётся обычный выбор файла. Offline upload не заявлен готовым: бинарные вложения требуют доступного сервера.

## MIME / Size Rules

Backend и frontend согласованы по безопасному минимуму:

- фото: `jpg`, `png`, `webp`, до 10 МБ;
- файлы: `pdf`, `txt`, до 15 МБ;
- видео: `mp4`, `webm`, `mov`, до 50 МБ, только для разрешённых сценариев.

Неподдержанный тип и превышение размера возвращают русские ошибки. Список MIME не расширялся за пределы уже существующего foundation.

## Архив файлов

`Архив → Файлы и вложения` читает metadata вложений без физического перемещения файлов. `storagePath` не возвращается в API/UI. Скачивание идёт только через `/attachments/:id/file` с проверкой доступа к исходному объекту.

Chat attachments видны только пользователям, которые видят соответствующий чат. Вложения задач, ОКК, возвратов, склада, чек-листов, мойки и объявлений проходят через исходные scope/permission checks.

## RBAC / Scope

Архив и download не расширяют права:

- WORKER не видит чужие вложения;
- STORE видит складские и возвратные вложения по правам;
- OKK видит ОКК-вложения по правам;
- TECH видит вложения адресованных заявок;
- MANAGEMENT ограничен своим scope;
- ADMIN видит доступное в выбранном заводе;
- guest не получает общий файловый архив;
- blocked и cross-factory доступ запрещены.
