# FINAL LIVING SYSTEM V1 - физический Android/PWA checklist

Текущий статус: `PHYSICAL_GATE_STATUS: PENDING_APPROVAL`  
`PHYSICAL_PHONE_GATE: PENDING`

Этот checklist не является доказательством PASS сам по себе. PASS фиксируется только после проверки пользователем на физическом телефоне.

## Runtime перед проверкой

- Backend health: локально PASS.
- Frontend: локально PASS.
- Публичный HTTPS URL: не создан.
- QR: не создан.
- Причина: Cloudflare Quick Tunnel требует отдельного разрешения на публичную экспозицию тестового стенда.
- Backend использует случайный process-local signing secret; значение `.env` не требуется и не раскрывается. Production startup без настроенного секрета отдельно запрещён guard-ом.

## Безопасный способ запуска после разрешения

1. Проверить текущие PID на портах `3000` и `5173`.
2. Backend оставить на месте, если `/health` отвечает.
3. Текущий Vite dev-server заменить на production preview того же build на порту `5173`; в canonical Vite config уже разрешён host `.trycloudflare.com`.
4. Поднять один прямой Quick Tunnel только к `http://127.0.0.1:5173`.
5. Проверить external `/`, `/api/health`, `/health`, bearer login, `/auth/me`, WebSocket, manifest, service worker и offline page.
6. Smoke остаётся read-only по бизнес-данным: не создаёт sandbox, чат, error-report или attachment.
7. Создать QR только для чистого HTTPS URL без query/hash и оставить backend/frontend/tunnel запущенными.

Старый `scripts/mobile-pilot/start-quick-tunnel-pilot.ps1` для этого gate не запускается: он предназначен для отдельного diagnostic sandbox и создаёт тестовые записи.

## Проверка на телефоне

1. Открыть выданный HTTPS URL и убедиться, что нет белого экрана.
2. Зарегистрировать новый тестовый номер и убедиться, что профиль имеет только Guest/Pending.
3. Проверить повтор номера в форматах `+7` и `8`: дубль не создаётся.
4. Подать заявку на назначение и принять её уполномоченной ролью.
5. Убедиться, что меню и права обновились без повторного входа.
6. Выполнить управляемый reset пароля; старая вкладка и WebSocket должны потерять доступ.
7. Проверить назначение сотрудника, WorkArea и STOP/возврат линии в рамках роли.
8. В чате проверить текст, ответ, реакцию, фото из камеры и галереи, просмотр вложения и микрофон/voice note.
9. Проверить уведомления, физический push и vibration после разрешения браузера.
10. Пройти периодический checklist без закрытия всего цикла после одной проверки.
11. Проверить клавиатуру, sticky actions, safe-area, нижнюю навигацию и Android Back на 360-430 px.
12. Обновить страницу, свернуть/вернуть PWA, отключить/включить сеть и проверить reconnect.
13. Установить PWA на главный экран и проверить повторный запуск.
14. Проверить ожидаемое offline-состояние без ложных сохранений.

## Что сообщить после проверки

- модель телефона и версия Android;
- браузер и установлен ли PWA;
- какие пункты 1-14 пройдены;
- точный экран и действие при ошибке;
- screenshot ошибки, если она возникла;
- итог: `PASS` или список фактических проблем.
