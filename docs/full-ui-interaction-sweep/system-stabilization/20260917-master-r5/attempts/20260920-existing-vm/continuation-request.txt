— request000007: EXIT_COORDINATOR;

PID из отчёта — исторический ориентир, не текущая доказанная identity.

Сначала проверь фактическое состояние:
— VM по GUID;
— helper по PID + start time + command line;

— выполняющуюся Hyper-V операцию, если она есть;
— наличие terminal receipt.

Не считать отсутствие receipt доказательством, что команда не запускалась. Не считать timeout доказательством отмены.

До прояснения очереди НЕ:
— отправлять новые BOOT/SHUTDOWN/KEYS;
— запускать второго изменяющего контроллера;
— удалять или переименовывать старые requests;
— переписывать results как будто команда завершилась;
— начинать установку, которую затем может прервать отложенный SHUTDOWN.

Если старый helper завершён, отдельно проверь фактическое завершение операции в Hyper-V. Завершение helper не обязательно означает завершение запрошенного действия.

Если helper ещё работает, сначала выясни, где он остановился, и используй штатное завершение только при понятном состоянии.

Force/TurnOff/Reset VM, принудительное завершение vmwp/vmms, broad kill всех PowerShell/Node и перезагрузка хоста НЕ разрешены этим продолжением.

Если безопасно завершить старую операцию нельзя — сообщи точный request/job/state и требуемое решение, не создавай обходной контроллер.

Главная гарантия: при возобновлении установки не должно оставаться старой команды, которая неожиданно выключит гостя.
