# Передача: review documents и неизменные source bytes

Один ZIP имеет repository-relative layout и корневой START-HERE.md. Все активные относительные Markdown-ссылки текущих R4 документов проверяются относительно ZIP entries. Entry manifest/export plan находится внутри; внешний receipt после полного readback связывает ZIP SHA/bytes/count. Внутренний plan перечисляет payload; сам plan и link-audit перечислены во внешнем исполняемом package-plan — это явное исключение self-hash cycle, не пропуск payload.

Исторические документы и snapshots родительских Markdown передаются **как raw source text** с суффиксом `.source.txt`: байты не перекодируются и не редактируются. Относительные ссылки внутри этих исходных текстов относятся к их прежнему owner/context, а не превращаются в обещание включить все многогигабайтные архивы истории. Link audit перечисляет такие ссылки отдельно, с фактической проверкой наличия в исходном repo и признаком включения в пакет. Это не current clickable review navigation и не PASS недостающим файлам. Entry manifest содержит точное соответствие original source → archive name/hash/bytes.

Current parent progress/gap/README представлены полными before/after raw bytes, manifest и diff. Их текущий R4 смысл изложен в final-report/root-result; старые даты и разрешения внутри raw history не действуют вместо текущего поручения. Старые screenshot ZIPs не перезаписываются и не становятся обязательными частями R4 review. Новые R4 before/failure/final PNG включены целиком; число VIEWED указано отдельно.

Существующий R3 `handoff/export-plan-full.json` включён неизменным по original SHA. Он описывает старый R3 ZIP, **не** entries R4; отсутствие в R4 всех2018старых entries не означает потерю этих файлов. Собственные R4 required source/test/log/native материалы самодостаточны. node_modules/.env/БД/uploads/credentials/cookies/storageState/.git/private keys исключены. Runtime installation/данные для live-acceptance не входят: стенд не был создан, scripts не запускать автоматически.
