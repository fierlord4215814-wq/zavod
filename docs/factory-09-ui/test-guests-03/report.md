## Подтверждённые пробелы и непроверенное

1. **BLOCKER для полной роли MANAGEMENT №9:** текущий ADMIN-only guard для организационных/UFA действий не позволяет начальнику производства законно управлять своим заводом. Не исправлять глобальным ADMIN или снятием factory/RBAC guards; нужен отдельный минимальный factory-local контракт с негативными проверками.
2. **Подрядные должности:** UI grant назначает фирму/роль, но не department/job; backend требует department у job title, тогда как contractor context запрещает department. 3 contractor-профиля пока без jobTitle. Нужна согласованная адресная модель/owner, не SQL-обход.
3. **Межзаводские специалисты №4↔№9:** существующим трём тестовым сотрудникам №4 пока не выдан новый №9 UFA, потому что отдельный action-time допуск на расширение доступа запрошен, но не получен в момент этого отчёта. Новые №9 технические гости не заменяют «тот же человек в двух заводах». Task/source/archive, общий чат и недвойной опыт для №4↔№9 **NOT_RUN**.
4. Другие роли получили штатный вход и negative scope readback, но отдельные сценарии STORE, механика, электрика, холодильщика, сантехника, старшего/сырьевого мастеров, полного contractor labor/attendance, мойки/оттайки/остатков и полноценной истории смен не закрыты. STORE Марина вошла в обычном браузере и видит завод №9 и пустой экран «Заказы / Остатки» (0 позиций, 0 заявок), но кнопок создания позиции/заявки нет: `STORE` по текущему permission catalog намеренно не имеет `orders.items.manage`/`orders.request` без индивидуального grant. Допуск на расширение этих прав не получен; пустой экран не выдаётся за проверку складской операции. Второе окно без F5, внешний push, телефон и фактические 12/24 часа также не проверены.
5. В Task detail автор/исполнитель/комментарий показаны как маскированный «Пользователь +7…», хотя canonical имя известно в других разделах; в detail события линии актор показан как «Сотрудник». Причины source consumer отдельно не исправлялись. Checklist local archive summary «0 из 2» — ещё один UX-дефект. Не объявлять эти отображения готовыми.
6. Учебные аккаунты имеют короткий тестовый credential только в локальной `mes`; они не должны попасть на публичный VPS. Нужен отдельный точный план блокировки/смены credentials/исключения до публикации, без удаления локальной истории.
