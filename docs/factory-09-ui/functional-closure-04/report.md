## Точные ограничения выполнения

- Три прежних тестовых TECH сверены read-only: `pilot-tech-kipia-1` / `79000004750` / TECH_KIPIA; `mobile-tech-electric` / `79000009105` / TECH_ELECTRIC; `mobile-tech-holod` / `79000009106` / TECH_HOLOD. У всех активный non-guest UFA №4; у каждого есть и другие старые UFA, которые нельзя менять. Новых UFA №9 пока нет. Перед адресной UI-выдачей требуется ответ на действие-time подтверждение браузерного инструмента, несмотря на исходное согласие пользователя; без него зависимые задачи не выполнять.
- Начальник Андрей: User `ea808f6b-d580-56af-a63c-fb65713d7b7f`, MANAGEMENT/№9, локальный title `c1b5ab6c-6447-4030-9a02-1b7155b050e4`. В текущей БД local overrides профиля не выданы. UI-выдача также ожидает action-time подтверждения.
- Два независимых браузерных origin: `localhost:5173` сейчас сеанс STORE Марины №9 с незавершённой формой учебного возврата; `127.0.0.1:5173` сейчас сеанс мастера Бориса №9. Старые пользователи №4/их права не менялись.
- При штатном «Отправить домой» Ульяна исчезла из live-списка на смене (`2→1`), но SQL после операции оставил её ShiftSession `e4ad2b06-3a7c-42cf-b1af-1a4bb0e7bcb5` в `ACTIVE/endedAt=NULL`. Это **новый воспроизведённый разрыв состояния** между `EmployeeState.OFF_SHIFT` и ShiftSession; не считать явку завершённой и не исправлять историю прямой БД-записью. Линия остановлена, Assignment завершён. Исходная ранее активная учебная явка Николая не тронута.
- Точный owner разрыва: `EmployeeService.sendHome` в `backend/src/modules/employee/employee.service.ts` закрывает Assignment и меняет `EmployeeState`, но не закрывает найденную ACTIVE `ShiftSession`; отдельный `ShiftService.closeShiftSessionTx` используется обычным self-end и maintenance. Согласованное объединение транзакции/аудита/credit/WS и отрицательные тесты нужно проверять отдельно; в этом блоке не расширяли рискованную логику времени без полной проверки. До неё `SHARED_SHIFT_VISIBILITY_SINGLE_COUNT=NOT_ACCEPTED`.
