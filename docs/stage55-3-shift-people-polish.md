# Stage55.3 — Смена, люди, службы: tiny polish

## Discovery result

Существующая модель уже разделяет live-назначения и план будущей смены:

- `Assignment` остаётся только текущей/live работой.
- `PlannedLineAssignment` хранит будущие назначения по `shiftDate + shiftType`.
- `LineShiftWorkPlan` уже подходит для плановых линий будущей смены.
- `/lines/:id/planning-board` создаёт план линии только при явном выборе линии/шаблона.

Новая миграция не потребовалась.

## Что исправлено

- Вкладка `Будущие` теперь открывает конкретную выбранную будущую смену, а не подменяет её ближайшей `Следующей`.
- `/shift/future` принимает `targetShiftDate + shiftType` и возвращает план выбранной смены.
- Плановые линии показываются только если линия явно добавлена в план выбранной смены.
- Для worker/contractor плановые линии доступны только read-only, без кнопки добавления и без доски назначений.
- Профиль службы показывает лёгкий статус: `Сейчас на заявке` или `Свободен`.
- Pilot scenario получил `Тестовый электрик 1` в отделе `Электрики` с доступом к `Завод 4`.
- Список людей подсвечивает сотрудников на смене.
- Повременщики оставлены как явная доска слотов: сначала слот, затем сотрудник; список кандидатов компактнее.

## Future planning

`Следующая` остаётся быстрым planning-screen ближайшей смены.

`Будущие` сначала показывает список смен, затем выбранная смена раскрывается тем же planning-flow:

- отметки `Я буду`;
- плановые линии;
- конкретные слоты;
- назначение и освобождение;
- профиль человека.

Будущие назначения не влияют на текущие счётчики и live-занятость.

## Service status

Для КИПиА, холодильной службы, электрика, механиков, сантехников, технологов, ОКК и склада профиль проверяет активную заявку `IN_PROGRESS`, где пользователь указан как исполнитель/взявший/активный assignee.

Это не производственное назначение и не влияет на сменные счётчики.

## RBAC

Backend остаётся источником истины:

- WORKER/CONTRACTOR видят плановые линии read-only.
- MASTER/MANAGEMENT/ADMIN могут добавлять линии в план и назначать слоты по существующим правам.
- Заблокированные пользователи не получают runtime-доступ.
- Служебные роли не попадают в кандидаты назначений.
