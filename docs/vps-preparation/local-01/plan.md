## Решения и ограничения

- Для Windows functional C0 использовать канонические backend/frontend build, PREP-01 foundation/bootstrap и только собственный PostgreSQL. Существующие Compose/Dockerfile/setup остаются владельцами будущего Linux deployment C0; второй installer не создавать.

- Исторически пять live gates и следующий ролевой пласт были отложены; поручение 24.09.2026 разрешило пять gates и применимые ролевые сценарии **после** C0. UI 014/050, legacy replay и expired/future publication без фактов/политики не решать догадками; общий UI Sweep остаётся на паузе.

Новое поручение явно заменяет прежнюю рекомендацию Docker Desktop: разрешены **одна собственная Ubuntu 24.04 LTS в WSL2 и Docker Engine + Compose plugin внутри неё**. Для Docker — [официальный стабильный apt-репозиторий](https://docs.docker.com/engine/install/ubuntu/) с keyring и `Signed-By`, проверкой `apt-cache policy`; без `curl | sh`, без docker-группы для приложения и TCP daemon. `systemd` только если штатно доступен в этом WSL; [Microsoft описывает проверку](https://learn.microsoft.com/en-us/windows/wsl/systemd). Все команды/exit/stdout/stderr через PowerShell → `wsl -d <точное имя> -- ...`; VMConnect не использовать. До установки Docker проверить, что Ubuntu и WSL действительно поднялись.

При UAC refusal или reboot останавливаемся с точной точкой продолжения, не обходим и не повторяем запрос автоматически.
