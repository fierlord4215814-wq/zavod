- Все перечисленные крупные модули имеют текущий UI entry и backend owner. Ни один целый модуль не объявлен пропавшим по одной отсутствующей таблице/кнопке у запрещённой роли.
- **PROVEN_MISSING**: frontend decision/list UI для `ShiftReturnRequest` при существующей форме отправки «Запрос отправляется мастеру» и GET/PATCH `/shift/return-requests`. Source search всего `frontend/src` нашёл только singular POST `/shift/return-request`. Новый смысл решения не придумывался.
- **PROVEN_DEAD**:30 неработающих config flags из [точного списка](remaining-gaps.md); C UFA→sendHome compatibility link даёт409 после успешного назначения; журнал→второй открытый UI не refresh (retained L03).
- **EXPECTED_HIDDEN**: Guest ordinary screens; WORKER/CONTRACTOR chats; full Admin у не-ADMIN; phone/архив/чужой factory по guard; retained `smoke`/diagnostic fixtures. Это не новые missing modules.
- **DEFERRED**: три explicit reserved настройки; два legacy defrost flags для today UI superseded Stage37. v1 goal отдельно откладывает ERP/1С, offline binary sync, BI сверх текущих экранов, внешний realtime и Stage68; их не восстанавливали как «потерянный v1».
- **UNKNOWN / NOT_VERIFIED**: кто должен инициировать self start/end UI (есть API, LOCAL03 не доказал UI contract); duplicate factory-name uniqueness policy, factory clone/import/export, work-area complete Admin lifecycle, полный contact/analytics/error-report корпус, две естественные checklist time boundaries, все inline-edit Back/keyboard permutations. Нужен owner-specific follow-up, не новый whole-project Sweep.
