- Предпочтительный clean launch: новая серверная БД, migrations + минимальная системная основа + явно проверенные справочники; без полного локального dump и без `backend/prisma/seed.js`.
- Вымышленные сотрудники и искусственная рабочая активность не должны появляться после restart/update. Причина прежнего постоянного присутствия `UNKNOWN`: проверить source-first seed/bootstrap/startup, `ShiftSession`/`Assignment`/plans и frontend fallback/cache. Не отключать scheduler и не скрывать реальных сотрудников ради симптома.
- При отсутствии рабочих данных UI должен показывать корректные пустые состояния.
- Локальная среда, автотесты и isolated fixtures сохраняются отдельно; они не являются production data.
- До будущих действий с рабочими данными нужен согласованный backup DB + uploads + защищённых настроек, проверка восстановления и retention. На этом checkpoint `DATA_BACKUP=NOT_PERFORMED`, `DATABASE_CLEANUP=NOT_PERFORMED`.

## 7. Границы будущего VPS-теста

Исходные sizing inputs: до 200 пользователей; примерно одна фотография каждые 30 секунд суммарно по заводу; Linux VPS в Москве до 5000 ₽/месяц; позднее перенос на сервер предприятия. Provider, IP и domain не выбраны. Эти значения — требования для оценки, не performance proof.

До допуска тестировщиков обязательно доказать на clean stand:

1. Clean DB provenance, `migrate deploy` result и отсутствие demo seed/startup repopulation.
2. Safe first ADMIN bootstrap, credential rotation, factory scope, UserFactoryAccess, RBAC/blocked/cross-factory denial.
3. TLS/domain/session/cookie/CORS/WS settings без раскрытия secret values.
4. Persisted uploads, MIME/size/ownership/revoke, backup pairing DB↔uploads и test restore plan.
5. Health/readiness/logging, controlled restart and empty-state behavior.
6. Пять named live gates, затем applicable journeys; только после этого targeted UI063 и финальная regression.
7. Отдельные safe fixtures и их bounded cleanup; никаких реальных business writes.

Не мешают **подготовке** ограниченного VPS-теста сами по себе: незавершённый локальный Hyper-V repair, старый UAC blocker и P2 визуальные/physical вопросы, если они явно перечислены и не затрагивают security/data integrity. Но physical Android/PWA/media должен быть пройден до соответствующей мобильной эксплуатационной приёмки.

Неподтверждённые предпосылки: Linux compatibility текущего setup path; безопасный first ADMIN; production secret injection; фактическая storage growth/retention для фото; resource sizing и concurrency до 200 users; provider networking/backup; источник persistent fake staff; clean empty screens на actual API; переносимость на будущий enterprise server.
