## 3. Пакет и решение о переходе

Исходный OPS [ZIP](review-pack-ops01-20260927.zip) **не изменён**: 59 695 210 bytes, SHA-256 `aae2524a6ff7397081e6641332c7fc4d365445fbe0181a53ac828d465328dec1`. Независимо прочитаны все 344 entries; [manifest](review-pack-manifest.json) задаёт 343 файла, 344-й — сам manifest; у каждого entry совпали length/SHA, дублей/пропусков/неожиданных файлов нет. На момент проверки все 343 source-файла тоже совпали с manifest. После этой сверки обновлены только актуальные docs, так что новая редакция указателей находится **вне неизменённого ZIP**. ZIP checksum доказывает целостность старого пакета, а не бизнес-правильность. В этой среде нет штатной операции вложить локальный ZIP в ChatGPT; путь/размер/SHA передаются явно, публичной загрузки нет.

Решение последовательно: **(1)** пользователь решает судьбу T1 с учётом `INSUFFICIENT_EVIDENCE` и при желании заказывает узкую protected row-review, **(2)** только отдельное разрешение на закрытую техническую Linux/Compose/VPS-приёмку, **(3)** отдельно — допуск обычных пилотных пользователей после remaining gates/policy/phone по применимости. Новая серверная БД — foundation + первый ADMIN + проверенные справочники/шаблоны, **не перенос T1 целиком**. Ни OPS KPI 86/86, ни меню, ни документ «отложено» не являются запретительным guard или пилотным допуском.
